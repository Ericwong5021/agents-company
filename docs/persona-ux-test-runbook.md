# Persona UX Test 真实环境盲测 Runbook

> 状态：当前
> 更新日期：2026-07-30
> 适用范围：Agent Company WebUI

本文规定如何让隔离 Subagent 以精准用户画像操作真实产品 UI，并产出不受源码、设计文档或既有缺陷污染的体验报告。它补充[体验重构计划](product-design/Agent-Company-Experience-Refactor-Plan-v1.0.md)中的可用性测试要求，不替代真实用户研究、SUS 或发布 Gate。

全局执行能力由 `persona-ux-test` Skill 提供；本文只保存 Agent Company 的项目级测试合同和运行方式。

## 1. 强制边界

- 测试者只读取指定的 [README.zh.md](../README.zh.md)。
- 测试者不得读取源码、设计文档、`AGENTS.md`、Git、测试、数据库、内部日志或网络接口。
- 测试者只通过 Browser 操作 WebUI。
- 主持者只负责准备运行环境、提供入口和处理工具级中断，不解释正确导航。
- 找不到入口、概念不懂、错误不可恢复均属于体验证据。
- 不执行部署、上传、OTA、发布、付款、外部消息、批量删除或其他不可逆动作。
- API Key、Token 和账号不得写入本文、报告、截图说明或 Subagent 消息。

## 2. 标准用户画像

| 维度 | 基线 |
|---|---|
| 身份 | 陈晓宇，34 岁，成都独立亲子活动工作室负责人，团队 3 人 |
| 技术水平 | 会用 macOS、微信、Notion、飞书和 ChatGPT，不会编程 |
| 业务任务 | 推出“周末亲子自然观察营” |
| 购买动机 | 希望本地 AI 公司围绕目标自行组队、持续推进，而不是单轮聊天 |
| 核心顾虑 | 数据离开本机、AI 越权、失败不可恢复、没有可用成果 |
| 使用环境 | MacBook，中文为主，每天可投入 30 分钟 |
| 行为特征 | 首次使用、无培训；一个卡点按直觉尝试两次后停止 |
| 成功标准 | 得到目标用户、活动流程、安全风险、定价假设和两周启动计划 |

更换画像时必须完整定义身份、技术水平、业务背景、动机、顾虑、环境、行为和成功标准，不能为现有界面量身定制。

## 3. 主持者准备

### 3.1 创建隔离测试者

- 创建无历史上下文的独立 Subagent。
- 只提供用户画像、README 路径、任务、允许的 UI 工具、凭证和安全边界。
- 不提供既有缺陷、预期路径、页面说明或内部术语解释。
- 要求报告区分 `实际观察`、`用户推断` 和 `未能验证`。

### 3.2 WebUI

主持者在仓库根目录启动：

```bash
bun run dev:all
```

确认本地 WebUI 可访问后，仅把产品入口交给测试者。启动命令、端口诊断和终端输出不交给测试者。

## 4. 凭证规则

1. Base URL 与 API Key 只在任务消息中临时提供。
2. 测试者到达真实保存动作时，必须取得用户当时的明确确认。
3. 只通过产品 UI 输入、测试和保存，不修改配置文件。
4. 不接受浏览器或系统密码管理器的云端保存建议。
5. 包含完整凭证的界面不得截图。
6. UI 不可读、焦点不确定或可能误存时立即停止。
7. 报告只写“已保存”“未保存”或“无法确认”，不复述凭证。

## 5. 核心测试任务

向 Agent Company 提交：

> 为成都 8–12 岁儿童设计一个周末亲子自然观察营 MVP，给出目标用户、活动流程、安全风险、定价假设和两周启动计划。

按以下顺序测试：

1. 理解首屏产品定位和本地数据边界。
2. 完成首次启动、Company Home 和模型配置。
3. 创建或进入公司。
4. 提交目标并启动执行。
5. 观察谁在工作、为什么组队、当前进度、失败和待审批事项。
6. 查看 Thread、Agent、Board、Inbox、制品和交付。
7. 遇到错误时按普通用户方式恢复一次，单个卡点最多尝试两次。
8. 保留环境可恢复，不删除测试数据。

## 6. 证据与严重度

| 证据类型 | 定义 |
|---|---|
| 实际观察 | 测试者在真实 UI 中亲自看到或操作得到 |
| 用户推断 | 测试者根据界面形成的理解，可能与内部机制不同 |
| 未能验证 | 因入口、权限、错误或时间限制无法确认 |

| 级别 | 判定 |
|---|---|
| P0 | 产品无法进入，或核心目标完全不可开始 |
| P1 | 核心任务受阻、事实不可信、失败不可恢复或存在明显安全风险 |
| P2 | 明显理解成本、导航摩擦或领域定位偏差 |
| P3 | 视觉、措辞或操作细节问题 |

页面存在、模型自述、Fixture、自动化或本地日志不能替代用户实际理解。模拟 Persona 报告也不能把[弱门禁登记](product-design/pre-public-acceptance-register.md)中的真人验收状态改为已确认。

## 7. 报告结构

报告必须包含：

1. 用户画像、测试环境和信息隔离声明。
2. 各任务完成度。
3. 带时间顺序的关键体验。
4. 亮点。
5. 问题清单：严重度、场景、UI 复现步骤、实际结果、用户影响和证据类型。
6. 用户不理解的术语。
7. 信任、隐私和安全感。
8. 是否愿意继续使用或付费。
9. Top 5 改进建议。
10. 未能验证范围。

报告不得引用源码或设计文档，不提供工程实现方案，不把工具故障直接判定为产品故障。

## 8. 收尾

- 停止本轮启动的 WebUI 和 Control Plane 开发进程。
- 不擅自删除 Company Home、数据库、配置或测试目标。
- 向用户列出留下的目录和数据，以及是否可安全恢复。
- 确认没有部署、上传、OTA、发布或不可逆外部动作。
- 把人工研究和真实样本继续登记为独立弱门禁；模拟 Persona 只提供问题发现证据。
