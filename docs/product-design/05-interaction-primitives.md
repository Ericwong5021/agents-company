# 05. 交互原语

> **模块**：交互原语
> **核心问题**：Agent 之间怎么沟通协作
> **来源**：运转模型宪法 §7 + 群聊 PRD

---

## 1. 交互范式

无状态 runtime 下交互是**回合制 / 信箱式**：消息在任务边界产生与消费。

---

## 2. 核心记录：AgentMessage

Agent 间通信的基础数据结构：

| 字段 | 说明 |
|------|------|
| ID | 消息唯一标识 |
| FromAgentID | 发送者 |
| ToAgentID | 接收者 |
| Kind | 消息类型：fyi / request / reply / proposal |
| Body | 消息内容 |
| Classification | 密级，随消息传递 |
| ThreadID | 委派链/会话共享 |
| RootNeedID | 贯穿全链路的根需求 |
| IssueID | 触发本消息的源任务 |
| SpawnedIssueID | request 派生的子任务 |
| InReplyTo | reply 指向的 request |
| Depth | 每次 delegate +1 |

---

## 3. 核心原语

### 3.1 message_agent（FYI）

- **语义**：告知，不建任务
- **行为**：建消息 + 发事件，不触发执行
- **寻址**：按名字/角色 + 沿组织树向上解析

### 3.2 delegate（Request）

- **语义**：委派任务
- **行为**：建消息 + 创建子任务分配给目标
- **深度**：每次 delegate +1，有上限
- **寻址**：同 message_agent

### 3.3 reply（Reply）

- **语义**：任务完成回流
- **行为**：子任务完成时自动建消息回流给原请求方
- **消费**：不自动排任务；发事件 + 标未读

### 3.4 propose（Proposal）

- **语义**：自底向上提案（delegate 的镜像）
- **行为**：建消息向上流，上级采纳/搁置/否决
- **方向**：向上（delegate 向下）

### 3.5 read_doc

- **语义**：查阅授权内文档
- **行为**：走同一套 ACL 门控读单文档
- **审计**：命中发访问事件

---

## 4. 防环 / 防爆炸

### 4.1 深度上限

- `MAX_DELEGATION_DEPTH` ≈ 组织树深度（默认 5）
- 超限拒绝并回灌错误

### 4.2 防自派

- `to == from` 拒绝

### 4.3 幂等去重

- 同 run 内 `(parent, to, body-hash)` 唯一

### 4.4 防爆炸

- 叶子调用总量 ≈ 分支因子（团队规模）× 重试 × 深度
- 由任务评级 + token 统计 / block 兜底

---

## 5. reply / FYI 回灌（回合制）

- reply / 未读 FYI 不自动排任务
- 发事件 + 标未读
- 目标 Agent 下次启动时注入并标已读（走响应模式）
- FYI 在 UI 即时可见、认知上回合制可见

---

## 6. 会议 / 纪要

### 6.1 董事会圆桌 = 系统入口

- 用户作为参与者加入一场 meeting
- meeting = 多 Agent 产出汇入一个 thread 的扇入聚合
- 生成 minutes，由有权者提升为 public

### 6.2 两个 primitive 即可表达大部分协作拓扑

- `delegate`（扇出）+ `meeting`（扇入）
- 无需 DAG 引擎

### 6.3 纪要是沉淀产物

- 「会议记录 / 人事变动 / 职责调整」是交互的沉淀产物
- 非人手写静态文档

---

## 7. 协作自主声明

### 7.1 Agent 自主发起协作

- 常驻上下文有名册 + 专长（profile）
- Agent 判断「我做不了 / 别人更专业」→ 主动发起
- 两个方向：
  - 沿组织树**向上汇报/求决策**
  - 按专长**找平级协作**

### 7.2 对齐 A2A 协议

- profile = Agent Card（能力发现）
- delegate/message_agent = 发起
- 子任务生命周期 + reply = 执行/回结果
- 现有 AgentMessage 即承载，不另造协议

## 8. 群聊体验

### 8.1 产品目标

- 群组主界面从「调用 supervisor 工作流」转向「多人 Agent 群聊房间」
- 在一条共享时间线中逐条展示用户与 Agent 的发言
- 给用户对发言节奏的可见控制

### 8.2 发言策略

| 策略 | 说明 |
|------|------|
| **auto** | 保持现有 supervisor/LLM 决策体验 |
| **round_robin** | 按成员顺序轮流发言 |
| **manual** | 由用户点选下一位发言者 |

### 8.3 信息架构

- **左侧**：群组与话题导航
- **中间**：共享群聊主时间线
- **右侧**：成员与发言控制面板
- **顶部**：全局状态栏（策略/轮次/状态/控制）
- **底部**：输入区

### 8.4 成员状态

| 状态 | 说明 |
|------|------|
| idle | 空闲 |
| thinking | 正在生成前准备或等待模型响应 |
| speaking | 正在输出消息 |
| queued | 已排队，等待发言 |
| muted | 本轮或全局静音 |
| error | 该成员执行失败 |

### 8.5 控制能力

- 查看下一位发言者和当前队列
- 切换发言策略
- 设置最大轮次
- 对单个成员：点名、静音、跳过本轮
- 暂停、继续、停止队列
