# 07. 工作类型

> **模块**：工作类型
> **核心问题**：不同类型的工作怎么做
> **来源**：运转模型宪法 §1.5

---

## 1. 核心理念

> 一家公司的工作远不止编码——董事会有 CMO/CFO。编码只是**一种**工作类型，叶子工具因类型而异。

---

## 2. 通用契约（所有工作类型同构）

执行层永远做同一件事：

```
细化成 spec（目标 + 验收标准）→ 选对工作流 → 驱动工具产出 → 提交准入
```

`spec + workflow` 是普适骨架，与工作类型无关。

### 2.1 统一交付抽象

```
隔离工作区 → 产出 artifact → 提交准入
```

- 编码 = 隔离工作区 + PR
- 非编码 = workspace 文档树里的带密级文档

### 2.2 验证设施按类型

| 工作类型 | 验证设施 |
|----------|----------|
| 编码 | 测试 CLI / 仿真环境 |
| 研究 | 溯源核查 |
| 设计 | 渲染对比 |
| 分析 | 重算 |

---

## 3. 形态插件（随工作类型而变）

### 3.1 编码

| 维度 | 说明 |
|------|------|
| 工作流/工具 | CLI 编码工具 |
| 产物形态 | 代码（git repo） |
| 验证/准入方法 | 测试 / build / lint + PR diff 评审 |

### 3.2 研究/调研

| 维度 | 说明 |
|------|------|
| 工作流/工具 | 检索 / 浏览 / 抓取 |
| 产物形态 | 报告（workspace 文档） |
| 验证/准入方法 | 溯源 + 事实核查 + 跨源交叉验证 |

### 3.3 写作/文案

| 维度 | 说明 |
|------|------|
| 工作流/工具 | 写作工具 |
| 产物形态 | 文稿 |
| 验证/准入方法 | rubric 评审 + 事实核查 + 与 brief 比对 |

### 3.4 设计

| 维度 | 说明 |
|------|------|
| 工作流/工具 | 设计/生成工具 |
| 产物形态 | 设计资产 |
| 验证/准入方法 | 渲染 + 对 brief 视觉评审 |

### 3.5 分析/财务

| 维度 | 说明 |
|------|------|
| 工作流/工具 | 数据/表格/计算 |
| 产物形态 | 模型/分析 |
| 验证/准入方法 | 重算 + 假设审计 + sanity check |

### 3.6 决策/规划

| 维度 | 说明 |
|------|------|
| 工作流/工具 | 发散 + 评估 |
| 产物形态 | 方案/建议 |
| 验证/准入方法 | 多方案对比 + 准入评判 |

---

## 4. 非编码交付物

- 非编码交付 = workspace 文档树里的带密级文档
- 组织的交付物本来就是它的文档树
- 代码只是「住在 git 仓库、走 PR」的特例

---

## 5. 验证设施 = 公共设施

- 组织建一次、全员共用
- 让 review 真跑真看（验不是品）
- 同时给做的人提交前自检（shift-left）——大降 review 拒绝率
- 搭这些设施本身是组织的元任务

---

## 6. 经验 → 技能结晶

### 6.1 沉淀路径

```
深度态（发散/专注）run 结束
  → 反思收尾：写私有 memory
  → 重复多次同类任务
  → 结晶成 skill
  → 写入公共设施 + Agent 个人 skills/
  → 喂回 SkillIDs 访问控制
```

### 6.2 学习闭环

环境扫描 → 提案 → 权限内试验 → 见效 → 上级批准入生产 → 结晶成 skill。执行闭环（自顶向下）之外的第二条闭环：**组织能力自生长**。
