# 02. 执行模型

> **模块**：执行模型
> **核心问题**：Agent 怎么跑、并发怎么管
> **来源**：运转模型宪法 §2

---

## 1. 核心概念：身份与执行解耦

推翻「Agent ≈ 一个工人 = 一次只干一件事」的隐含前提。

| 概念 | 本质 | 特性 |
|------|------|------|
| **Agent** | 一束持久文件（soul/instruct/memory/skills/relationships/kanban） | 持久的**身份**（「谁」） |
| **Model** | 大语言模型 | 瞬时的**执行**（「在做」） |
| **Thread** | 并发执行单元 | 并发计量单位 |

**关键洞察**：
- 一份身份可被**多次点燃**：同一束文件可同时被多个模型 run 动画化
- "busy" 应问「主线占了没」，而非「这 Agent 忙不忙」

---

## 2. Agent 文件束

每个 Agent 是一束持久文件，定义其完整身份：

| 文件 | 职责 |
|------|------|
| **soul.md** | 稳定身份：名字、角色、职责、组织归属、工作风格 |
| **instruct.md** | 可演化指令：该角色如何做判断、如何沟通、何时升级 |
| **memory/** | 私有记忆：工作记录、经验教训、反思沉淀 |
| **skills/** | 私有技能：经验结晶后的可复用能力 |
| **relationships.md** | 同事关系：协作偏好、沟通风格、信任度 |
| **kanban.md** | 个人任务视图：手头项目、待办、进度 |

### 文件束特性

- **全员持久化**：不招募即弃。董事会/部门负责人持久无疑；底层职员同样持久
- **经验沉淀**：哪怕只干过一次，工作记录也是下次同类任务的路径参考
- **技能结晶**：重复多次的任务结晶成 skill，喂回公共设施
- **空闲不耗**：空闲 Agent 几乎不耗 token

## 3. 线程模型

### 3.1 线程种类

| 线程 | 模式 | 资源 | 并发限制 |
|------|------|------|----------|
| **主线 Primary** | 专注/发散 | 独占隔离工作区、长 run、重预算 | 每 Agent ≤ 1 |
| **响应线 Reactive** | 响应 | 独立 scratch、短 run、轻预算 | 每 Agent ≤ N（限流） |
| **环境线 Ambient** | 空闲 | 只读探索、极低频低预算 | 受调度限流 |

### 3.2 主线（Primary）

- 用于执行核心任务
- 独占隔离工作区（编码=worktree，非编码=group 文档草稿区）
- 长时间运行，重预算
- 每个 Agent 同时只能有 1 条主线

### 3.3 响应线（Reactive）

- 用于处理碎片交互（FYI/reply 回灌）
- 独立 scratch 空间
- 短时间运行，轻预算
- 每个 Agent 可并发多条（限流防滥用）

### 3.4 环境线（Ambient）

- 用于空闲时的环境扫描
- 只读探索
- 极低频、低预算
- 受调度器限流

## 4. 并发管理

### 4.1 Presence / 活动登记

- per-agent 活动线程登记表：当前线程 + 在做什么 + 状态
- 派活前先查，防重复分配
- 处理中的事不可被标 queued

### 4.2 状态聚合

- `AgentStatus` 从单枚举升级为 per-thread status + agent 级 rollup
- 对外状态 = 线程状态聚合投影

### 4.3 共享文件束写竞争

- 并发线程只在 run 启动时透过持久文件交流，不共享活上下文
- 主线独占隔离工作区
- 响应线只读为主 / 写独立 scratch
- memory/kanban 写串行化

---

## 5. 时延剖面

### 5.1 同步 vs 异步

- **圆桌同步**：用户在场、快速来回
- **派发后全异步**：提需求 → 通知交付

### 5.2 串行 vs 并行

- **深度串行**：~4-5 跳协调，有界
- **宽度并行**：同层兄弟节点 = 多线程并发

### 5.3 重试放大

- 重试（×2）是有界放大器
- 协调开销相对叶子真活儿是小头

### 5.4 时延吸收

- 时延靠「圆桌同步 + 执行异步 + 兄弟并行」吸收
- 超大项目仍慢，靠进度可观测缓解
