# 04. 注意力模式

> **模块**：注意力模式
> **核心问题**：Agent 在想什么、用什么档位
> **来源**：运转模型宪法 §6

---

## 1. 模式定义

模式描述 Agent 的**注意力状态**，与职业/runtime 无关。

**框架：注意力 = 广度 × 深度**

|  | 浅（低投入 / Flash 模型） | 深（高投入 / 强模型） |
|---|---|---|
| **宽（扫描多目标）** | 🟢 空闲 idle | 🟡 发散 divergent |
| **窄（锁定单目标）** | 🔵 响应 reactive | 🔴 专注 focused |

---

## 2. 四态详解

### 2.1 空闲（Idle）

- **类比**：浅思 / 探索社交
- **前景**：公司愿景、组织架构、profile、公共看板；以探索为主
- **静音**：项目代码细节、他人项目
- **模型档位**：Flash（廉价）
- **用途**：环境扫描 + 社交，非休眠

### 2.2 响应（Reactive）

- **类比**：处理碎片交互、回信箱
- **前景**：仅本次交互对象 + 最小上下文，轻载
- **静音**：项目深层、组织战略、社交探索
- **模型档位**：Flash（廉价）
- **用途**：信箱廉价消费者

### 2.3 发散（Divergent）

- **类比**：脑暴、创意、规划、拆解
- **前景**：当前问题/项目 group-scope、（协作时）他人输入
- **静音**：社交、其他项目、行级细节
- **模型档位**：强模型
- **用途**：管理者节点的主要模式

### 2.4 专注（Focused）

- **类比**：执行、达成、准入评判
- **前景**：当前目标细节（代码/文档/diff/数据）、相关 skill·规范
- **静音**：社交、其他项目、组织战略
- **模型档位**：强模型
- **用途**：执行层的主要模式

---

## 3. Mode-Profile 结构

每个模式定义一个 profile：

```
mode-profile = {
  foreground,           // 前景：注入什么上下文
  muted,                // 静音：忽略什么
  inject_vs_explore,    // 注入 vs 探索比例
  enabled_tools,        // 启用哪些工具
  budget_split,         // 预算分配
  model_tier            // 模型档位
}
```

**安全红线所有模式常驻，不可静音。**

---

## 4. 模式 = 成本旋钮

模式同时决定「注入什么」+「用哪档模型」：

| 模式 | 模型档位 | 成本 |
|------|----------|------|
| 空闲 | Flash | 极低 |
| 响应 | Flash | 低 |
| 发散 | 强模型 | 高 |
| 专注 | 强模型 | 高 |

这让「全员持久化」在成本上成立：空闲 Agent 几乎不耗 token。

---

## 5. 模式默认与切换

### 5.1 粗粒度默认

| 状态 | 默认模式 |
|------|----------|
| 无任务 | 空闲 |
| 处理信箱 | 响应 |
| 承接任务（管理者） | 发散 |
| 承接任务（执行层） | 专注 |

### 5.2 模式切换驱动

- **主路径 — 生命周期推导**：在 run 边界由 Agent 状态、issue 上下文、inbox 未读状态自动推导
- **兜底 — 自主切换**：Agent 在 run 内可自主请求切换，受模式永不扩权约束

### 5.3 模式切换规则

- 模式随 run 边界切换，无需中途改写
- 切换发审计事件
- 单 run 内限频

---

## 6. 反思收尾

- **仅深度态（发散/专注）结束后触发**
- 浅度态不触发
- 是动作非状态——把产出/所学写入私有 memory
- 按需更新 kanban / relationship
- 回答「Agent 何时写记忆 = 每次深度工作之后」

---

## 7. 正交修饰

- **独自 vs 协作** = 横切 flag，由 Agent 主动置位
- 决定是否注入他人输入
- 不是额外模式，是模式的修饰

---

## 8. Idle = 环境扫描 + 社交

- idle 触发低频低预算的环境性 run
- leader 扫领域新技术 / 方法论
- Agent 社交
- 产出提案
- 这是 idle 的主要用途，非休眠
